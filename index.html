The logic

What the check actually does

  1. 01

    Read the magic bytes

    Identify the real format from its first bytes (PK, D0CF11E0, %PDF) — not the file extension.

  2. 02

    Unpack the container

    Unzip OOXML parts, read OLE compound-file streams, walk PDF objects, decode RTF hex blobs.

  3. 03

    Walk the risky parts

    Relationship files, vbaProject.bin, drawing & object streams, PDF action dictionaries.

  4. 04

    Decompress & read the code

    Inflate MS-OVBA macro streams to source, extract DDE fields and PDF /JS.

  5. 05

    Match the danger rules

    Auto-run, shell, downloads, and TargetMode="External" / /OpenAction remote fetches.

  6. 06

    Decide the verdict

    SafeDangerous + proof

Peephole flags macros, active scripts and automatic network requests — the behaviours behind most document-borne attacks. It is a strong first look, not a full antivirus. A file called “safe” has none of those behaviours in the parts Peephole can read; always weigh where a file came from. Your file is checked entirely in your browser and never uploaded — the only thing ever sent is an anonymous +1 to the shared counter.
